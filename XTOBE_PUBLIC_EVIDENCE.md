# XTOBE public evidence policy

## Purpose

This registry defines the standard for public evidence in XTOBE materials. It intentionally favors conservative status declarations and only promotes a project or system when there is verifiable evidence connected to source-controlled work.

## Status model

- Concept
- Designed
- Implemented
- Tested
- Bench-validated
- Pilot-validated
- Deployed

## Verification rules

A status may only move upward when the following are available:
- Source repository or commit reference
- Relevant test or validation command
- Actual observed result
- Verification date
- Traceable evidence URL or artifact

Any claim based only on documentation, slideware, or marketing language remains at its highest conservative status unless independently verified.

## Current public evidence posture

This repository is intentionally not claiming public benchmark, pilot, or deployment results without traceable evidence. The current design and profile work are treated as brand and identity development rather than technical validation claims.

## Example of acceptable evidence

- GitHub Actions run with clear pass/fail output
- Unit or integration test command executed in a public workflow
- Bench validation recorded in a repo artifact or release note
- Pilot evidence tied to a specific implementation record and date

## Observed principle

The XTOBE identity should communicate scientific ambition and engineering competence without overstating maturity. Evidence records remain public, specific, and traceable.
